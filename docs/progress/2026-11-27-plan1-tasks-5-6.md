**Gotchas**
- The owner runs `/code-review` and wants to **review before each commit**. Ask before
  committing as well as before merging.
- Never add Co-Authored-By or "Generated with" lines.
- Merging uses the REST API: `gh api -X PUT …/pulls/N/merge -f merge_method=squash`. Update a
  stale branch with `…/update-branch`.
- `@dms/db/testing` is for tests only: it throws outside Vitest, and a hygiene test checks this.
- **Packages with DB tests:** use `dbTestConfig("<prefix>")` in their `vitest.config.ts`.
- **Test app pool:** has one connection. In concurrency tests, release any open transaction in
  `finally`, or every later test hangs.
- **Writes to `data_keys`:** the guard trigger can reject them (`DMS01`). Destroyed rows are
  immutable.
